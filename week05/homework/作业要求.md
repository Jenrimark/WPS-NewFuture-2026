服务健康探测器
一、 项目背景
在现代云原生架构中，实时监控成百上千个服务的可用性是后端开发者的核心职责。本项目要求你开发一个高性能的命令行工具（CLI），能够并发探测多个网络目标的健康状况，并输出一份直观的性能分析报告。
二、 核心目标 
1. 动态配置与目标解析
• 目标： 系统需支持通过外部配置文件（JSON 格式）定义多个监控目标。
• 核心逻辑： 能够识别不同的探测协议（如 HTTP、TCP），并根据配置加载对应的执行逻辑。
2. 高并发探测引擎
• 目标： 充分利用 Go 语言的并发优势，实现“瞬间”扫描所有目标。
• 性能要求： 无论配置文件中有多少个目标，程序必须在极短的时间内并行启动所有探测任务。
• 健壮性： 必须具备超时控制机制，确保任何一个目标的阻塞不会导致整个程序挂起。
3. 数据流转与结果聚合
• 目标： 安全地收集来自不同并发任务的探测结果。
• 数据一致性： 必须确保在多协程环境下，结果的收集和汇总不会发生数据竞态。
• 执行流控制： 必须确保所有探测任务彻底完成后，才触发最终报告的生成。
4. 智能报表与分析
• 目标： 提供一份具有工程参考价值的 CLI 汇总报告。
• 分析要求： 统计成功/失败比例、响应时间分布、并筛选出表现最差（响应最慢）的服务。

四、 命令行交互规范
程序需支持以下命令行参数：
• --config: 指定配置文件的路径（默认 config.json）。
• --timeout: 单次探测超时时间（单位：秒，默认3）。
• -v: 开启详细模式，实时打印每一个目标的探测状态。
