## 关键实现思路

1. **阶梯电价（先算“基础电费”）**  
   按用电量落在的区间分段累加：
   - 不超过 200 度：全部按 **0.5 元/度**；
   - 200～400 度：前 200 度按 0.5，超出 200 的部分按 **0.8 元/度**；
   - 超过 400 度：前两段同上，超过 400 的部分按 **1.2 元/度**。  
   实现上先判断当前电量落在哪一档，用“已计入的度数 + 本档单价”方式累加，避免重复分支错误。

2. **峰谷调节（再乘到总价上）**  
   题目要求峰谷是对**总费率**的增减，因此实现为：  
   **最终电费 = 阶梯基础电费 × 时段因子**。  
   区间采用数学上的左开右闭写法（与作业表述一致）：  
   - **高峰 (8:00, 22:00］**：**不含** 8:00 整点，**含** 22:00 整点 → 因子 **1.10**（+10%）。  
   - **低谷 (22:00, 次日 8:00］**：**不含** 22:00 整点，**含** 次日 8:00 整点。在「当日 0:00–23:59」内等价于：**0:00–8:00（含 8:00）** 与 **22:01–23:59** → 因子 **0.80**（−20%）。  
   实现：把 `HH:MM` 换成「从 0:00 起的分钟数」`m`，高峰当且仅当 `480 < m <= 1320`（即大于 8×60、小于等于 22×60）。

3. **时段输入**  
   使用 `strings.Split` 与 `strconv.Atoi` 解析 `HH:MM`；**峰谷判断使用小时与分钟**（例如 **8:00 为低谷，8:01 为高峰**；**22:00 为高峰，22:01 为低谷**）。

4. **`main` 循环**  
   持续提示输入；对负数电量、解析失败给出提示并重新输入。

## 阶梯电价实现中的困难与难点

- **边界归属**：200、400 度恰好落在档间时，必须明确“本档是否含等号”，否则会和手算差一度电价；实现时用同一套区间划分并在测试中固定边界用例校验。  
- **区间端点是否含等号**：(8:00, 22:00］与 (22:00, 次日 8:00］在 **22:00 整点**同时只属于高峰（右闭）而不属于低谷（左开），**8:00 整点**只属于低谷；必须用**时+分**判断，不能再用「整点小时」模糊处理。  
- **峰谷作用对象**：是“每度单价阶梯后再打折”还是“阶梯总价再乘因子”；按题意取**总价乘因子**，与“总费率增加/减少”一致。  
- **浮点误差**：金额用 `float64` 累加时，测试中使用小epsilon比较，避免 `==` 误判。
